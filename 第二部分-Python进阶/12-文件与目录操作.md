## 12.1 为什么要操作文件

程序运行结束后，内存里的数据就消失了。要想**持久保存**数据（比如把结果写进文件、下次读回来），或者**读取外部数据**（比如一份成绩单、一个数据集），就需要文件操作。这也是通往数据分析的必经之路。

---

## 12.2 打开与关闭文件

基本流程：打开 → 读/写 → 关闭。

```python
f = open("test.txt", "w", encoding="utf-8")   # 打开
f.write("你好，文件")                            # 写入
f.close()                                       # 关闭（很重要！）
```

`open()` 的常用参数：

- 第一个参数：**文件路径**。
- 第二个参数：**模式**。
- `encoding`：**编码**，处理中文强烈建议写 `"utf-8"`，否则在某些系统上会乱码或报错。

> **为什么要写 `encoding`？** 计算机里存的其实是数字，“编码”就是“数字 ↔ 文字”的对照表。中文常见的对照表有 `utf-8` 和 `gbk` 两种。**写入和读取必须用同一张表**，否则就会乱码或报 `UnicodeDecodeError`。中文 Windows 默认用 `gbk`，macOS/Linux 默认用 `utf-8`——所以不写 `encoding` 的代码，换一台电脑就可能出错。统一写 `encoding="utf-8"` 最省心。

### 文件到底在哪儿？（相对路径）

`open("test.txt", ...)` 只写了文件名，没写完整路径，这叫**相对路径**。它是相对于“**当前工作目录**”的——也就是你**在哪个文件夹里运行** `python` 命令，而**不一定**是 `.py` 文件所在的文件夹。

```python
from pathlib import Path
print(Path.cwd())    # 打印当前工作目录：相对路径都从这里算起
```

新手常遇到“明明文件就在旁边，却报 `FileNotFoundError`”，或者“写出来的文件不知道跑哪去了”，十有八九就是这个原因。解决办法：

- 用 VS Code 打开**项目文件夹**，在内置终端里运行；
- 或者先 `cd` 到脚本所在文件夹再运行；
- 或者在代码里以脚本自身位置为基准拼路径（12.6 节会讲 `pathlib`）：

```python
from pathlib import Path
BASE = Path(__file__).parent          # 当前 .py 文件所在的文件夹
data_file = BASE / "test.txt"         # 无论在哪里运行，都指向脚本旁边的 test.txt
```

（`__file__` 只在运行 `.py` 文件时才有；在 `>>>` 交互模式和 Jupyter Notebook 里没有这个变量。）

### 文件打开模式

| 模式 | 含义 | 文件不存在时 | 文件已存在时 |
| --- | --- | --- | --- |
| `"r"` | 只读（默认） | 报错 | 从头读 |
| `"w"` | 写入 | 新建 | **清空**后写入 |
| `"a"` | 追加 | 新建 | 在末尾追加 |
| `"x"` | 独占创建 | 新建 | 报错 |
| `"r+"` | 读写 | 报错 | 可读可写 |

> ⚠️ **`"w"` 模式会清空原文件内容**！如果只是想在文件末尾添加内容，一定要用 `"a"`（追加）模式。

## 12.3 with 语句（推荐做法）

手动 `close()` 容易忘记，一旦中途报错还可能导致文件没正常关闭。**`with` 语句**能自动帮我们关闭文件，是官方推荐的写法：

```python
with open("test.txt", "w", encoding="utf-8") as f:
    f.write("第一行\n")
    f.write("第二行\n")
# 缩进块结束，文件自动关闭，无需手动 close()
```

从今往后，**请一律使用 `with` 来操作文件**。它属于“上下文管理器”，能确保资源被正确释放。

## 12.4 写入文件

```python
lines = ["苹果", "香蕉", "橙子"]

with open("fruits.txt", "w", encoding="utf-8") as f:
    for fruit in lines:
        f.write(fruit + "\n")       # write 不会自动加换行，要手动加 \n

# 或者用 writelines 一次写入多行（它同样不会自动加换行）
with open("fruits.txt", "w", encoding="utf-8") as f:
    f.writelines([fruit + "\n" for fruit in lines])
```

> `write()` 只接受**字符串**：`f.write(5)` 会报 `TypeError: write() argument must be str, not int`，要写成 `f.write(str(5))` 或 `f.write(f"{5}\n")`。

**追加**内容（不清空原文件）：

```python
with open("fruits.txt", "a", encoding="utf-8") as f:
    f.write("葡萄\n")
```

## 12.5 读取文件

### 一次性读取全部

```python
with open("fruits.txt", "r", encoding="utf-8") as f:
    content = f.read()        # 返回整个文件的字符串
    print(content)
# 苹果
# 香蕉
# 橙子
# 葡萄
```

> 读出来的内容**永远是字符串**，哪怕文件里写的是数字。要计算就得先转换，比如 `int(line.strip())`。

### 逐行读取（推荐处理大文件）

直接对文件对象用 `for` 循环，会一行一行地读，非常省内存：

```python
with open("fruits.txt", "r", encoding="utf-8") as f:
    for line in f:
        print(line.strip())    # strip() 去掉每行末尾的换行符
```

### 读成列表

```python
with open("fruits.txt", "r", encoding="utf-8") as f:
    lines = f.readlines()      # 每行作为一个元素，含换行符
    print(lines)               # ['苹果\n', '香蕉\n', ...]
```

> **注意**：`read()` 后再 `read()` 会得到空字符串，因为“读取位置”已经到文件末尾了。文件像一个磁头，读过就往后走。

## 12.6 用 pathlib 处理路径

现代 Python 推荐用 `pathlib` 模块处理文件路径，它比字符串拼接更安全、跨平台：

```python
from pathlib import Path

p = Path("data") / "fruits.txt"   # 用 / 拼接路径，跨平台
print(p)                           # data/fruits.txt

print(p.exists())                  # 文件是否存在
print(p.name)                      # fruits.txt（文件名）
print(p.suffix)                    # .txt（扩展名）
print(p.parent)                    # data（父目录）

# 创建目录（parents=True 自动创建多级，exist_ok=True 已存在也不报错）
Path("output").mkdir(parents=True, exist_ok=True)

# pathlib 还能直接读写小文件
Path("hello.txt").write_text("你好", encoding="utf-8")
print(Path("hello.txt").read_text(encoding="utf-8"))
```

判断文件是否存在，再决定读还是写，是很常见的模式：

```python
from pathlib import Path

path = Path("config.txt")
if path.exists():
    print(path.read_text(encoding="utf-8"))
else:
    print("配置文件不存在，使用默认设置")
```

## 12.7 读写 CSV 文件

CSV（逗号分隔值）是最常见的表格数据格式，Excel 也能打开。标准库 `csv` 模块可以处理它：

```python
import csv

# 写入 CSV
data = [
    ["姓名", "年龄", "城市"],
    ["小明", 18, "北京"],
    ["小红", 20, "上海"],
]
with open("people.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.writer(f)
    writer.writerows(data)      # 一次写入多行

# 读取 CSV
with open("people.csv", "r", encoding="utf-8") as f:
    reader = csv.reader(f)
    for row in reader:
        print(row)              # 每行是一个列表
```

> 写 CSV 时加 `newline=""` 参数，能避免在 Windows 上出现多余空行。到了第三部分，我们会用更强大的 **Pandas** 来读写 CSV，但理解底层原理很有帮助。

> **用 Excel 打开 CSV，中文全是乱码？** 这是因为中文版 Excel 默认按 `gbk` 读取，而文件是 `utf-8`。写文件时把编码改成 `encoding="utf-8-sig"`（带一个特殊标记的 utf-8），Excel 就能正确识别了；用 Python 读取时 `utf-8` 和 `utf-8-sig` 都能读。

> `csv.reader` 读出来的每个格子都是**字符串**：`['小明', '18', '北京']` 里的 `'18'` 要 `int()` 后才能参与计算。

## 12.8 综合示例：日志记录器

```python
from datetime import datetime

def log(message, filename="app.log"):
    """把带时间戳的日志追加到文件。"""
    timestamp = datetime.now().strftime("%Y-%m-%d %H:%M:%S")
    with open(filename, "a", encoding="utf-8") as f:
        f.write(f"[{timestamp}] {message}\n")

log("程序启动")
log("用户登录")
log("程序结束")

# 读出来看看
with open("app.log", "r", encoding="utf-8") as f:
    print(f.read())
```

## 新手常见错误

### ❶ 找不到文件

```python
open("data.txt", encoding="utf-8")
```

```
FileNotFoundError: [Errno 2] No such file or directory: 'data.txt'
```

**原因**：常见的有三种——文件名拼错（包括扩展名，比如其实是 `data.txt.txt`）；文件不在**当前工作目录**；用 `"r"` 模式打开了一个还不存在的文件。
**改法**：先 `print(Path.cwd())` 看看程序“站在”哪个文件夹；用 `Path("data.txt").exists()` 检查；或改用 `Path(__file__).parent / "data.txt"`（见 12.2 节）。

### ❷ 编码不一致

```python
# 文件是用 utf-8 保存的，却没写 encoding（中文 Windows 默认用 gbk 去读）
open("cn.txt").read()
```

```
UnicodeDecodeError: 'gbk' codec can't decode byte 0xad in position 26: illegal multibyte sequence
```

**原因**：写入用的是 `utf-8`，读取用的是 `gbk`，对照表不一致（`can't decode` = 无法解码）。反过来，用 `utf-8` 去读 `gbk` 文件会报 `'utf-8' codec can't decode byte ...`。
**改法**：读写都显式写 `encoding="utf-8"`。如果文件是别人给的、用 `utf-8` 读报错，试试 `encoding="gbk"`。

### ❸ 用 `"w"` 模式把原文件清空了

```python
with open("diary.txt", "w", encoding="utf-8") as f:   # 想追加，却用了 w
    f.write("今天的日记\n")
```

**原因**：`"w"` 会先**清空**文件再写。这个错误**不会报错**，但之前的内容已经找不回来了。
**改法**：追加内容一律用 `"a"`。对重要文件动手前，先备份一份。

### ❹ 用写模式打开，却想读取

```python
with open("x.txt", "w", encoding="utf-8") as f:
    f.read()
```

```
io.UnsupportedOperation: not readable
```

**原因**：`"w"` 模式只能写，不能读（`not readable` = 不可读）。
**改法**：读取用 `"r"` 模式，单独再 `open` 一次。

### ❺ 在 `with` 块外面操作文件

```python
with open("x.txt", "w", encoding="utf-8") as f:
    pass
f.write("a")
```

```
ValueError: I/O operation on closed file.
```

**原因**：离开 `with` 的缩进块后，文件已经自动关闭了（`closed file` = 已关闭的文件）。
**改法**：所有读写操作都要缩进在 `with` 块里面。

### ❻ 文件被其他程序占用（Windows 常见）

```
PermissionError: [Errno 13] Permission denied: 'people.csv'
```

**原因**：文件正被 Excel 等程序打开着，Windows 不允许同时写入；或者路径指向的是一个文件夹、没有写权限的位置。
**改法**：先关闭 Excel 再运行程序；检查路径是否正确。

## 本章小结

- `open(路径, 模式, encoding="utf-8")`；处理中文务必指定 utf-8 编码。
- 模式：`r` 读、`w` 写（**会清空**）、`a` 追加。
- **一律用 `with open(...) as f:`**，自动关闭文件、更安全。
- 读取：`read()` 全部、`for line in f` 逐行、`readlines()` 成列表；`strip()` 去换行。
- 写入：`write()` 不自动换行，需手动加 `\n`。
- `pathlib.Path` 处理路径：`/` 拼接、`exists()`、`mkdir()`、`read_text/write_text`。
- 相对路径是相对于**当前工作目录**的；找不到文件时先 `print(Path.cwd())`。
- 读出来的内容都是字符串；给 Excel 打开的 CSV 用 `utf-8-sig` 编码。
- `csv` 模块读写表格数据。

def safe_read(path):

**第 5 题**：

```python
import csv

records = [["姓名", "成绩"], ["小明", 88], ["小红", 95], ["小刚", 72]]
with open("scores.csv", "w", newline="", encoding="utf-8") as f:
    csv.writer(f).writerows(records)

scores = []

    reader = csv.reader(f)
    next(reader)          # next() 取出“下一行”，也就是表头；取出来不用，就相当于跳过了

        scores.append(int(row[1]))

```
