## 18.1 pip：安装第三方库

Python 强大的地方在于有海量的**第三方库**（别人写好的、可以直接用的代码）。`pip` 是 Python 的包管理工具，从 [PyPI](https://pypi.org)（Python 包索引）下载安装它们。

```bash
pip install requests          # 安装名为 requests 的库
pip install numpy pandas      # 一次装多个
pip install "django>=4.0"     # 指定版本
pip uninstall requests        # 卸载
pip list                      # 查看已安装的库
pip show numpy                # 查看某个库的详细信息
```

> 如果 `pip` 命令不行，试试 `pip3`，或者 `python -m pip install ...`（最稳妥，明确用当前 Python 的 pip）。

> **`pip` 是在终端里运行的命令，不是 Python 代码**。在 `>>>` 后面或 `.py` 文件里写 `pip install numpy` 会报 `SyntaxError: invalid syntax`。（Jupyter Notebook 里可以用 `%pip install numpy`。）

### 下载太慢？换国内镜像

在国内直接访问 PyPI 经常很慢甚至超时（报 `ReadTimeoutError`）。可以临时指定国内镜像源，例如清华大学镜像：

```bash
pip install numpy -i https://pypi.tuna.tsinghua.edu.cn/simple
```

或者一劳永逸地设为默认源：

```bash
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

### 安装名 ≠ 导入名

大多数库安装和导入用的是同一个名字（`pip install numpy` → `import numpy`），但有几个常见的例外，新手很容易装错：

| `pip install` 时写 | `import` 时写 |
| --- | --- |
| `scikit-learn` | `sklearn` |
| `pillow` | `PIL` |
| `opencv-python` | `cv2` |
| `beautifulsoup4` | `bs4` |
| `python-dateutil` | `dateutil` |

> 千万不要 `pip install sklearn`——那是一个早已废弃的空壳包，装上也用不了。

安装后就能直接 `import` 使用：

```python
import requests               # 需要先 pip install requests
resp = requests.get("https://api.github.com")
print(resp.status_code)       # 200
```

## 18.2 为什么需要虚拟环境

设想一个问题：项目 A 需要 `numpy 1.20`，项目 B 需要 `numpy 2.0`。如果所有库都装在同一个全局环境里，就会**版本打架**。

**虚拟环境**为每个项目创建一个**独立、隔离**的 Python 环境，各项目的依赖互不干扰。这是专业开发的标准做法，强烈建议每个项目都用虚拟环境。

好处：

- 隔离依赖，避免版本冲突。
- 环境可复现——把依赖清单给别人，对方能装出一模一样的环境。
- 不污染系统的全局 Python。

## 18.3 用 venv 创建虚拟环境

`venv` 是 Python 自带的虚拟环境工具，无需额外安装。

### 创建

在项目文件夹里运行：

```bash
python -m venv .venv          # 创建一个名为 .venv 的虚拟环境
```

这会生成一个 `.venv` 文件夹，里面是独立的 Python 解释器和库目录。

### 激活

激活后，`python`、`pip` 命令就指向这个隔离环境了：

```bash
# Windows (PowerShell)
.venv\Scripts\Activate.ps1

# Windows (cmd)
.venv\Scripts\activate.bat

# macOS / Linux
source .venv/bin/activate
```

激活成功后，命令行提示符前面通常会出现 `(.venv)` 字样。此时 `pip install` 装的库只会进入这个环境。

> **Windows PowerShell 报“禁止运行脚本”？** 第一次激活时，你可能看到：
>
> ```
> 无法加载文件 C:\...\.venv\Scripts\Activate.ps1，因为在此系统上禁止运行脚本。
> ```
>
> 这是 PowerShell 默认的安全策略。执行一次下面的命令（只对当前用户生效），然后重新激活即可：
>
> ```powershell
> Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
> ```
>
> 嫌麻烦的话，也可以换用 cmd，执行 `.venv\Scripts\activate.bat`。

### 我现在用的是哪个 Python？

“明明 `pip install` 过了，运行时还是 `ModuleNotFoundError`”——这是新手最常遇到的环境问题，原因几乎都是**安装库的 Python 和运行代码的 Python 不是同一个**。用下面的命令确认：

```bash
python -c "import sys; print(sys.executable)"
```

它会打印出当前 `python` 命令对应的解释器路径。激活虚拟环境后，路径里应该包含 `.venv`。

### 在 VS Code 里使用虚拟环境

VS Code 点 ▶ 运行时，用的是它自己选定的解释器，不一定是你刚激活的那个。设置方法：

1. 按 `Ctrl + Shift + P`（macOS 是 `Cmd + Shift + P`），输入 **Python: Select Interpreter** 回车；
2. 在列表里选择带 `.venv` 字样的那一项；
3. 之后新打开的内置终端会自动激活这个环境，▶ 运行也会用它。

VS Code 窗口右下角（或右上角）会显示当前使用的 Python 版本和环境名，可以随时点开切换。

### 退出

```bash
deactivate
```

> **提示**：`.venv` 文件夹不要提交到 git（体积大且和机器相关），应写进 `.gitignore`（本教程根目录的 `.gitignore` 已包含它）。

## 18.4 requirements.txt：依赖清单

如何把“我这个项目需要哪些库”记录下来、方便别人（或换台电脑的你）复现？答案是 `requirements.txt`。

**导出**当前环境的所有依赖：

```bash
pip freeze > requirements.txt
```

生成的文件形如：

```
numpy==2.1.0
pandas==2.2.0
matplotlib==3.9.0
```

**安装**依赖清单里的所有库（换新环境时）：

```bash
pip install -r requirements.txt
```

这就是本教程根目录 `requirements.txt` 的作用——一条命令装齐第三、四部分需要的所有库。

> 标准工作流：新建项目 → 建虚拟环境并激活 → `pip install` 需要的库 → `pip freeze > requirements.txt` 记录下来。

## 18.5 规范的项目结构

一个小型 Python 项目通常长这样：

```
my_project/
├── .venv/                # 虚拟环境（不提交 git）
├── .gitignore            # git 忽略清单
├── README.md             # 项目说明
├── requirements.txt      # 依赖清单
├── src/                  # 源代码
│   ├── __init__.py
│   ├── main.py           # 程序入口
│   └── utils.py          # 工具函数
└── tests/                # 测试代码
    └── test_utils.py
```

关键点：源代码集中放（如 `src/`），入口清晰（`main.py` 里用 `if __name__ == "__main__":`），依赖和说明齐全。良好的结构让项目易读、易维护、易协作。

## 18.6 PEP 8：代码风格规范

**PEP 8** 是 Python 官方的代码风格指南。遵守它能让你的代码整洁、专业、易读。核心几条：

- **缩进**用 4 个空格，不要用 Tab 混排。
- 运算符两侧、逗号后加空格：`x = a + b`、`f(a, b)`。
- 命名：变量/函数用 `snake_case`，类用 CapWords（大驼峰/PascalCase，如 `MyClass`），常量用 `ALL_CAPS`。
- 每行不宜过长（一般 ≤ 79 或 99 字符）。
- 顶层函数/类之间空两行，方法之间空一行。
- import 放文件顶部，标准库、第三方库、本地模块分组。

可以用工具自动检查和格式化：

```bash
pip install black flake8      # black 自动格式化，flake8 检查风格
black your_file.py            # 一键格式化
flake8 your_file.py           # 检查不规范之处
```

> VS Code 里安装 Python 扩展后，可以配置“保存时自动用 black 格式化”，非常省心。

## 18.7 类型注解（Type Hints）入门

Python 是动态类型语言，但从 3.5 起支持**类型注解**——给参数和返回值标注类型。它不影响运行，但能提升可读性、让编辑器给出更好的提示和错误检查：

```python
def greet(name: str, times: int = 1) -> str:
    return f"你好，{name}！" * times   # 重复 times 次

# 变量也能注解
age: int = 18
scores: list[int] = [88, 92, 79]

def average(nums: list[float]) -> float:
    return sum(nums) / len(nums)
```

- `name: str` 表示 name 应该是字符串。
- `-> str` 表示函数返回字符串。

类型注解只是“提示”，写错类型 Python 也不会报错（除非用 `mypy` 这类工具检查）。但在稍大的项目里，它能显著减少 bug、提升协作效率。数据科学库的文档也大量使用它，学会看懂很有必要。

## 新手常见错误

### ❶ 装了库，运行时还是找不到

```
ModuleNotFoundError: No module named 'numpy'
```

**原因**：库装进了 A 环境，代码却在 B 环境里运行。常见情形：装的时候没激活虚拟环境；VS Code 选的解释器不对；电脑上装了多个 Python。
**改法**：
1. 运行 `python -c "import sys; print(sys.executable)"`，看看当前是哪个 Python；
2. 用**同一个** Python 安装：`python -m pip install numpy`；
3. VS Code 里用 “Python: Select Interpreter” 选对环境（见 18.3 节）。

### ❷ 在 Python 里运行 `pip`

```python
>>> pip install numpy
```

```
SyntaxError: invalid syntax
```

**原因**：`pip` 是终端命令，不是 Python 语句。
**改法**：先 `exit()` 退出 `>>>`，回到终端再执行；Jupyter 里用 `%pip install numpy`。

### ❸ PowerShell 无法激活虚拟环境

```
无法加载文件 ...\Activate.ps1，因为在此系统上禁止运行脚本。
```

**原因**：PowerShell 默认禁止运行脚本文件。
**改法**：执行 `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser`，或改用 cmd 执行 `activate.bat`（见 18.3 节）。

### ❹ macOS / Linux 提示 “externally-managed-environment”

```
error: externally-managed-environment

× This environment is externally managed
```

**原因**：较新的 macOS（Homebrew 安装的 Python）和 Linux 发行版不允许直接往系统 Python 里 `pip install`，以免弄坏系统自带的工具。
**改法**：这正是该用虚拟环境的时候——先 `python3 -m venv .venv` 并激活，再 `pip install`。

### ❺ 下载超时 / 速度很慢

```
ReadTimeoutError: HTTPSConnectionPool(host='files.pythonhosted.org', port=443): Read timed out.
```

**原因**：访问国外的 PyPI 服务器网络不稳定。
**改法**：使用国内镜像（见 18.1 节）：`pip install 包名 -i https://pypi.tuna.tsinghua.edu.cn/simple`。

## 本章小结

- `pip install/uninstall/list/show` 管理第三方库；`python -m pip` 最稳妥；下载慢就换国内镜像。
- “装了还找不到”时，先用 `sys.executable` 确认当前用的是哪个 Python；VS Code 里用 “Python: Select Interpreter” 选择环境。
- **虚拟环境**隔离项目依赖：`python -m venv .venv` 创建，`activate` 激活，`deactivate` 退出。
- `pip freeze > requirements.txt` 导出依赖，`pip install -r requirements.txt` 复现环境。
- 规范项目结构：源码、依赖、说明、测试各就各位。
- **PEP 8** 风格：4 空格缩进、合理空格与命名；用 `black`/`flake8` 自动化。
- **类型注解** `def func(name: str) -> int:` 提升可读性与工具支持。

class MyClass:                 # 类名用 CapWords（大驼峰/PascalCase）
